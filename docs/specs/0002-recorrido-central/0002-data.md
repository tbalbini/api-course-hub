# Contratos del recorrido

## Summary

Cada captura describe lo que ocurrió y el reproductor selecciona hasta dónde observarla. Los datos de compra pertenecen al servidor; la navegación de eventos pertenece al navegador.

## Feature design

| Entidad | Campos y origen | Relaciones |
|---|---|---|
| Producto | sku `kit-api`, nombre Kit de interfaces, precio entero 8900, moneda PEN, constantes del servidor | Un producto puede pertenecer a varios pedidos |
| Pedido | id UUID generado por servidor; sku y cantidad de la entrada validada; total de precio por cantidad; estado `created`; fecha ISO del reloj servidor | Contiene un producto y cantidad de 1 a 5 |
| Registro de idempotencia | clave de header, huella del sku y cantidad, pedido creado | Una clave identifica una única creación durante la vida del proceso |
| Captura | id UUID, modo real o simulado, eventos, request, response, duración observada opcional | Contiene eventos ordenados y la evidencia de una operación |
| Evento | id, tiempo lógico, actor, acción, input, output, estado, dependencias, frontera, procedencia, contrato, tres explicaciones, código, error opcional | Dependencias apuntan a eventos anteriores de la captura |
| Reproductor | captura, cursor, running, velocidad | Selecciona un evento, no ejecuta efectos |

Los límites de memoria son 200 pedidos por proceso, sin borrado silencioso; al agotarlos se devuelve 429 y se explica el reinicio. Las claves tienen entre 1 y 100 caracteres. No se conserva información personal.

Las transiciones del reproductor son load, play, pause, next, previous, seek, replay y speed. Los cursores se acotan al intervalo válido. Llegar al final pausa. Replay vuelve al principio y arranca, salvo preferencia de movimiento reducido. Cambiar profundidad no modifica la captura.

Los escenarios simulados comparten etapas y bifurcan ante una condición. Un error de autenticación no ejecuta almacenamiento. Un timeout después de persistir conserva el efecto y declara que el cliente no sabe si la operación terminó. La petición duplicada usa una misma clave y muestra recuperación del resultado previo.

Los valores de simulación proceden de fixtures constantes y llevan esa etiqueta. No se generan bytes de paquetes, SQL ejecutado ni latencias inventadas como si se hubieran medido.
